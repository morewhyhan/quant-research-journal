# E0V1E64 第四轮：V14～V17 初始策略源码

2026-09-07。按用户要求先写四个独立版本，不运行收益回测，不修改服务器，不推送仓库。
年化3000%是后续研究目标，**不是这些源码已经达到的成绩或未来收益承诺**。

## 基准与文件

六份V5依赖文件从`../E0V1E64_R3`逐字节复制，原目录未修改。四个新类都直接继承
`E0V1E64_V5`，不继承V6或其他新候选。`r4_common.py`只提供第四轮的附加指标、时点与运行保护。
每个候选有同名`.py`策略和`.json`参数文件；JSON所有params与V5完全一致，初始实验常量在Python类中。

| 策略类 | 修改范围 | 未改变的部分 |
| --- | --- | --- |
| `E0V1E64_V14` | 同一根已完成K线，多币入场信号排序 | V5原信号、退出、止损、60/40预算，一个持仓名额 |
| `E0V1E64_V15` | 扩大强势盈利单进入延长的范围 | 原小盈利延长、60分钟上限、原止损与其他退出、仓位 |
| `E0V1E64_V16` | 新增持续反弹失败退出 | 原信号、仓位、原止损；原退出优先 |
| `E0V1E64_V17` | 回撤储备须当前信号合格才启用 | 原入场、退出、止损、60%基础预算、97%总投入上限 |

## 固定初始规则（未经收益调参）

### 公共新增指标与时间

- 5分钟K线：4小时收益=当前收盘/48根前收盘-1；1小时流动性代理=近12根`close×volume`之和。
- 2小时均线=24根收盘均值；其1小时变化与12根前的该均线比较。
- V5方向有利条件保持原义：多头收盘高于MA240且MA120比12根前高；空头反向。
  注意MA120/MA240在5分钟周期分别覆盖10/20小时，不是120/240分钟。
- 新的“强趋势”=上述V5方向条件 + 收盘在MA120有利一侧 + 2小时均线沿持仓方向变化
  + 最近4小时收益沿持仓方向为正。缺失/非有限数值不合格。
- 新回调条件只取`floor(current_time,5分钟)-5分钟`及之前的完整K线；最新K线若已过期则不触发新条件。
  这不等于全策略已经通过正式未来函数或实盘一致性审计。

### V14：同一时刻择优

1. 继承V5生成全部原始信号；不新增买卖信号。
2. 同一已完成K线、当前白名单内、跳过每币最初240根预热K线；排除多空冲突、同方向退出信号、
   无有效4小时收益、非正流动性代理的候选。
3. 市场基准是上述时刻已预热且有数据的白名单币4小时收益的中位数，不是固定BTC，也不以未来币池回填。
4. 多单强弱=本币收益-市场中位数；空单强弱=市场中位数-本币收益。
5. 分数=`0.50×V5方向有利(0/1)+0.30×候选强弱百分位+0.20×候选流动性百分位`。
   百分位使用当时所有候选平均秩；同分按币名、方向排序，不依赖白名单或回调遍历顺序。
6. 只确认排名最高且未被引擎锁定的候选。其余不下单；仍只有一个持仓名额、同一份资金。
   获胜者若因精度、最低金额等后续执行约束失败，不在本版自动递补，避免临时改变规则。
7. 排序异常时拒绝入场并记日志；不让引擎回调异常的默认放行行为变成“随机照旧开仓”。

实现采用普通回测的“先计算各币信号、再逐时处理交易”流程：在引擎移动信号到下一根之前保存
紧凑字段，每次排序只读取精确已完成时间。不能直接使用各币不同进度的DataProvider末行排序。
保存全期特征不等于允许读取未来：测试会给未来后缀注入极端值，并确认当前排名不变。
该缓存会占用额外内存，后续全年回测应串行执行。

### V15：盈利≥3%的优质单也允许延长

- V5原有0.5%≤盈利<3%的延长逻辑完全保留。
- 尚未进入延长、V5返回fastk盈利退出、当前盈利≥3%、满足公共强趋势时，进入同一个`v5_extension`状态。
- 不重置已开始的计时器；仍最多60分钟，保留`max(0.2%,已观察峰值利润×50%)`利润底线、
  V5趋势结束退出，以及其他原始退出。
- **没有放松原有止损，也没有覆盖ROI或强平。**例如原空单盈利达到3%时已有很紧的止损；
  它可能先退出，使本版实际增益很小。必须在后续回测报告中检查退出路径，不能声称“必然拿住大趋势”。

### V16：持续反弹失败退出

原V5若已有退出原因，优先返回原原因。否则必须同时满足：

1. 回调当前利润≤-6%，且持仓≥120分钟（不是触及-6%立即卖，也不是保证净亏不超过6%）。
2. 有连续12根、全部在入场之后完整形成的5分钟K线；缺K线/过期/非有限指标不触发。
3. 多单这12根收盘始终低于2小时均线，代表一小时未能收复；空单始终高于该均线。
4. 最近3根多单收盘均低于MA240且2小时均线低于其1小时前值；空单全部反向。

满足后返回`v16_failed_rebound_long/short`，由引擎正常退出。阈值只是一套初始假设，
不代表已证明能辨认所有“最终无法恢复”的交易。未使用最终输赢标签或未来最低/最高价。

### V17：有条件释放储备

- 沿用V5已实现钱包余额的高水位/回撤计算，不把浮盈亏混入新的仓位判断。
- 默认60%；只有当前完成K线有对应方向的原入场信号、无多空冲突/同方向退出，且满足公共强趋势，
  才使用原V5回撤梯度：回撤<5%用60%；5%～10%用约73.3333%；10%～20%用约86.6666%；≥20%用97%。
- 下一笔金额=`proposed_stake×目标比例/0.97`，不超过proposed_stake和max_stake。
  不满足最低下单金额就跳过，不为了满足最低金额突破预算。
- 不是给当前亏损单DCA，不增加杠杆，不注入外部资金；信号不合格时仍允许V5原交易用60%预算发生。

## 安全边界与继承问题

- 四个新版本只允许`backtest`模式、`max_open_trades=1`；拒绝live、dry_run、hyperopt。
  这是一套研究源码，不是可直接部署的生产版本。
- V5原始的空单min_rate方向问题、钱包高水位重启恢复缺失、全局持仓追踪状态未在此轮偷偷修正。
  将来若修正，必须另存基准与差异，不能与本轮效果混算。
- 原止损-25%及方向不同的custom_stoploss保留，不保证单笔损失封顶，也不保证账户回撤。
- 原白名单、手续费/资金费数据口径和引擎参数仍需在正式回测时锁定；源码不宣称2025资金费缺失已解决。
- 不并行或在同一进程内混跑多个候选收益回测，避免继承的全局状态污染。
